phase4: scan performance optimization (8x speedup)

Third step of Phase 4 (CLI). Optimize scan performance by sharing
runtimes across rules of the same file type, using IIFE isolation
to prevent scope pollution.

New method RquickjsRuntime::evaluate_rule_source:
- Wraps rule source in an IIFE (immediately invoked function
  expression) to isolate const/function/var declarations
- Prevents `detect` redeclaration conflicts when multiple rules
  share the same runtime
- Allows sequential evaluation of multiple rules in one runtime

Scanner refactoring (scan_bytes):
- Group rules by file type (Binary/PE/ELF/MACH/MACHOFAT)
- Create one runtime per file type group
- Load framework scripts (init + type init + includes) once per group
- Evaluate each rule in an isolated IIFE scope within the shared
  runtime
- Reduced from ~1186 runtime instances to ~5 (one per file type)

Performance improvement:
- Single file scan: ~8s -> ~1s (8x speedup)
- CLI integration tests: 8.56s -> 1.23s (7x speedup)
